# MIPD repository separation status

## Phase 1 — frozen extraction — COMPLETE

The executable engine, 46-model library, provenance, tests, Pmetrics fixtures
and frozen experimental ML artifacts were extracted from PMx commit
`2f97f109c3f4af257776a595f6546c9cd5f2321d` on 2026-10-16. Extraction
provenance remains recorded in `ORIGIN.md` and
`migration/source-manifest.json`.

MIPD-Engine is now the authoritative scientific and executable repository.
PMx Explain is a separately maintained educational consumer.

## Phase 2 — standalone public deployment — COMPLETE

The independent public application is deployed at the immutable source SHA
`fec16cbdf8e33ed6c791226ccf236761333f8de8`, Shinyapps bundle
`12702795`, app ID `17776160`. Rollback bundle `12702610` is retained.

Public acceptance covered HTTP availability, FR/EN websocket operation,
two-session behavior, synthetic PK, MAP and DDI paths, with arbitrary custom
C++ and Pmetrics disabled on the public host.

The release was performed through authenticated local rsconnect. GitHub
`production` deployment secrets remain unconfigured, so a later commit on
`main` does not imply that the public bundle changed.

## Phase 3 — PMx consumer cut-over — COMPLETE at the contract level

PMx has removed the executable R/Shiny `tdm-engine/` mirror. Its integration
contract now pins the exact deployed MIPD SHA `fec16cb`, app ID, bundle and
public fingerprint, and PMx CI verifies the standalone model catalogue,
metadata, source-review information, ML availability and compatibility.

Any browser-only materialization used by PMx is a generated consumer artifact.
The scientific model source is maintained only in MIPD-Engine and changes must
be qualified here before a PMx consumer pin can advance.

## Current standalone qualification

At the qualified code baseline `428d38f`:

- 46/46 model files compile and satisfy software contracts;
- frozen numerical software baselines cover all 46 models across 98 supported
  route/profile cases and 294 AUC/peak/C24 reference values;
- 13 experimental MAP priors have a numerical covariance/profile matrix;
- Roberts, Revilla and Goti have partial independent primary-source equation
  suites; 0/46 are claimed as complete independent primary-model
  reproductions;
- 0/46 are claimed as externally clinically validated;
- DOI and model/ML provenance gates are active.

The eight commits between the public source SHA `fec16cb` and qualified
baseline `428d38f` modify governance, documentation and qualification assets
only; they do not change `app.R`, `R/`, `models/`, `runtime/` or `renv.lock`.
The public Shiny bundle therefore remains an exact runtime/model deployment of
the frozen software even though repository-level qualification continued.

## Deferred research/operations — non-blocking after freeze

The following work remains research or operational hardening rather than a
reason to restore a monorepo:

- independent complete primary-source reproduction beyond the current partial
  equation suites;
- independent second review of the corrected Goti boundaries/MAP evidence;
- external clinical validation and documented-adaptation review;
- requalification of stale or underperforming experimental ML predictors;
- provider-side log/backup/retention audit;
- optional configuration of GitHub Shinyapps deployment secrets.

These items must remain explicitly separated from software-regression claims.

## Frozen ML artifact provenance

The 92 historical RDS artifacts copied during extraction remain explicitly
experimental. Migration preserved their provenance and does not upgrade their
validation status. Compatibility with a current model hash and predictive
performance are separate requirements.
